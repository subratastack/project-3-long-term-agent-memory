# Repository instructions for Codex and other agents

## Conceptual Markdown documentation

When creating or editing conceptual Markdown in this repository, follow
[the conceptual documentation standard](docs/conceptual-documentation.md).
Read that standard before making documentation changes. Use
[context-packing.md](docs/context-packing.md) as the worked style example.

Teach the problem and basic idea first, walk through realistic data and
outcomes, then introduce the algorithm, formulas, code, and limitations.
Verify behavior against the implementation and label illustrative numbers
separately from measured results. Apply this to the substance of the whole
guide, not just its introduction.

This applies to conceptual explanations in `docs/`, README sections, and
architecture guides. Preserve required ADR, API reference, and runbook
formats; use the same teaching principles where appropriate without forcing
a tutorial structure on every Markdown file.
